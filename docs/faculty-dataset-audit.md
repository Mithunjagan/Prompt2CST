# Faculty S11 sweep: preliminary audit

Source: [shared Google Drive dataset folder](https://drive.google.com/drive/folders/1fPOr9sO__1rw_TZOYmO8CbbLn5Dy0Fs0?usp=sharing), inspected 2026-09-24. This is a data source, not an instruction source. The original ZIP attachment was unavailable at the time of inspection, so this audit used the 52 text files visible in the folder rather than a local ZIP copy.

Each `design_NNN.txt` file has a `#Parameters = {...}` header and 1,001 sampled frequency/S11 pairs on an approximately 1–10 GHz axis: 52,052 sampled rows in total. The header exposes 13 numeric names (`a`, `b`, `c`, `d`, `e`, `h`, `l`, `lf`, `s`, `t`, `v`, `w`, `wf`). `b`, `l`, `lf`, `t`, and `w` are constant across the files; the other eight vary. Their physical meanings and units are **not** established by these files. The lowest S11 value observed in any one file ranges from about −12.52 to −41.32 dB. The lowest sampled point overall is in `design_044.txt`, around 4.699 GHz and −41.32 dB. These are readings from provided sweeps, **not** independently rerun simulation or measured antenna performance.

The header combinations form a one-factor-at-a-time sweep around `design_001.txt`: one baseline, seven alternative values each for `a`, `c`, `d`, `e`, `s`, `v`, and `wf`, and two alternatives for `h`. No file changes two of these parameters together. Thus the files can indicate local single-parameter trends but cannot identify interaction effects or validate arbitrary combinations.

This collection can support provenance-tracked comparison and, after topology and parameter mapping are supplied, a *topology-specific* surrogate or sensitivity study within its sampled domain. It cannot by itself teach a language model how to build any antenna. It does not cover 868 or 915 MHz, does not identify geometry, fabrication stackup, feed/port, solver settings, efficiency, or realized gain, and does not justify extrapolation outside the observed parameter ranges. The local LoRA prompt-extraction pilot does **not** train on these sweeps.

Before promoting this dataset to a geometry or optimization authority, obtain its associated CST project or parameter-to-geometry definition, units, substrate/material details, simulation setup, and confirmation of whether the curves are simulated or measured. Then validate the original files through the repository's `ingest-dataset` path and hold out complete designs—not individual frequency rows—for any surrogate-model evaluation.
